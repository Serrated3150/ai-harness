# Changelog

All notable changes to ai-harness. Projects pin a version and upgrade with
`harness sync` (docs/VERSIONING.md).

## Unreleased

Every change below is opt-in: the defaults keep v1.1.0's behaviour, so this
is a MINOR release (v1.2.0).

### Added

- **Run ledger** (`kit/scripts/ledger.mjs`, contract §ledger,
  `routines.ledger`). A run lists its whole scope at the start and records an
  outcome for every item. The harness stop hook sends the run back to work
  while any item has none, at most three times per run, and fails open. The
  ledger also keeps the run clock, so a "budget" stop is measured
  (`routines.budget`) and refused before the cutoff. Seen in a project: runs
  were summarising after two or three minutes, with most of their PRs "not
  checked".
- **Parallel subagents** (contract §parallel, `routines.parallel`). These cover
  how many subagents run at once, a worktree for each one that writes, what
  never runs in parallel, what a subagent gets and returns, and which state
  stays with the main agent. §picking-work takes up to `maxItemsPerRun` items
  per run.
- **Hand-off gate** (`review.handoff`, `review.fixNits`, §implementation).
  `"clean-approval"` hands a PR to the owner only once CI is green and the
  review bot has approved the head with no Blocker, Warning or Nit. With
  `fixNits`, Nits are fixed and pushed instead of carried.
- **Wait limits** (`routines.waits`): per-PR minutes, minutes per bot
  verdict, and fix cycles.
- Base routines (start of every run) read the run-discipline settings, and
  `harness-steward` and `harness-pr` follow the hand-off gate. The `core`
  section profile includes §parallel and §ledger.
- §roster recommends schedules where no two runs overlap.

### Fixed

- §implementation says how to wait for CI: never with a foreground `sleep`,
  which sandboxed sessions refuse and return from at once. Work on another
  item instead, or use the session's monitor tool or a background `sleep`.

## v1.1.0 — 2026-11-15

### Added

- **`harness-steward` skill**: the procedure for any agent or routine
  watching a PR it owns. It covers subscribing or scheduling check-ins,
  working every open item on each wake (conflict, red CI, harness-owned
  files, findings at every severity, branch-maintenance requests), handing
  off, and when to stop. The `pr-follow-through` base routine points to it.
- **Project-owned `steward` skill template**
  (`templates/project/.claude/skills/steward/SKILL.md`, seeded by `--init`).
  Claude Code reads `.claude/skills/steward/SKILL.md` from a PR's head branch
  before acting on PR events, so the project keeps its conventions there and
  follows `harness-steward` for the rest.
- **Dependabot for ai-harness** (`.github/dependabot.yml`), with
  `.github/workflows/action-pins.yml` as the pin source for the vendored
  workflows. `tools/pins.mjs --check` fails CI when `workflows/` drifts from
  it, and `--write` copies the pins across.

### Changed

- `harness-review` uses `anthropics/claude-code-action` v1.0.276 (was
  v1.0.268).
- `docs/ADOPTING.md`: keep a project's Dependabot off `harness-*` workflows
  with `exclude-paths`. Their pins arrive with harness releases.

## v1.0.2 — 2026-11-13

### Fixed

- **`harness-review` no longer fails on the install PR.** On a project's first
  install the base branch has no harness, so the review prompt cannot be built
  from it. The bot now skips that one PR with a notice, instead of failing,
  and never falls back to the PR's own prompt, which would let the PR write
  its own review. A person reviews the install PR, and `harness-check` still
  verifies its files against ai-harness.

## v1.0.1 — 2026-11-13

### Fixed

- **`sync` records the full commit SHA in the manifest.** `harness-check`
  fetches ai-harness by that exact commit to verify a sync PR, and a short SHA
  cannot be fetched.
- **The review checklist may use the prompt's placeholders.** It is inserted
  before `{{REPO}}`, `{{PR_NUMBER}}`, `{{BASE_REF}}` and `{{HEAD_SHA}}` are filled,
  so a project can ask the bot to emit a marker carrying the head SHA.

## v1.0.0 — 2026-11-13

### Added

- **Routine contract** (`kit/contract/ROUTINES.md`). The generic rules
  extracted from The Dial Book: precedence, roster, hard limits, markers,
  claims, picking work, status and type labels, order of work and
  dependencies, the state snapshot, triage, the plan gate, implementation,
  follow-through, templates, run summary, the self-learning loop and
  extension. Every section has an anchor.
- **Nine base routines** (`kit/routines/`), generated by
  `tools/gen-routines.py`, plus the loader prompt.
- **Config-driven scripts**: `sections`, `lessons`, `state`, `gates`,
  `verify` and `review-prompt`, with `lib/config` and `lib/glob`.
- **Hook engine**, config-driven, that makes harness-owned files read-only.
- **Skills** `harness-gates`, `harness-pr`, `harness-review`,
  `harness-extend`, `harness-issue`, and the agent `harness-reviewer`.
- **Workflows** `harness-review`, `harness-state` and `harness-check`.
- **`tools/sync.mjs`**: install and upgrade by vendoring, with a sha256
  manifest, settings merge and `--init` templates.
- **Docs**: boundaries, adopting, extending, config, versioning and
  contributing.
